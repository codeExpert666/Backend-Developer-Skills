本文把 VaultRAG 从一个技术想法收敛成可验收产品：明确目标用户、核心任务、MVP、失败语义、演示脚本和非目标。总体定位见 [[VaultRAG 项目实践总览]]。

> [!note] 状态说明
> 下文是待实现的产品合同，不表示当前已经存在 CLI、索引、API、评测或发布版本。

## 目标用户

首发只服务一种主要用户：

> 在自己的电脑上维护 Markdown 或 Obsidian 技术笔记，希望用本地模型提问，同时要求答案能引用原文、无法回答时明确拒答的个人开发者。

这个定义刻意排除团队协作、企业知识库、云端账号体系和跨用户权限。单用户并不意味着可以忽略安全，而是把安全重点放在本地文件、路径、进程边界和隐私泄漏上。

## 用户要完成的工作

### 建立可检查的索引

用户指定一个 vault 根目录后，系统应：

- 说明实际识别了多少 Markdown 文件、跳过了什么以及为什么。
- 在不修改源文件的前提下解析标题、Frontmatter、正文、代码块和 Wikilink。
- 为每个源版本和切片生成稳定、可追踪的标识。
- 展示新增、修改、删除、未变化和失败数量。
- 在配置或模型不兼容时要求重建，不能悄悄混用索引。

### 搜索而不生成

用户可以先执行纯搜索，检查系统找到了什么。搜索结果至少显示：

- 相对路径和标题层级。
- 内容摘要或受控长度原文片段。
- 关键词、向量和融合排名的可解释字段。
- 源内容散列或短版本标识。

纯搜索不依赖聊天模型；Embedding 不可用时，关键词搜索仍应工作。

### 提问并获得带证据回答

问答结果必须属于明确终态：

| 终态 | 用户看到什么 |
| --- | --- |
| ANSWERED | 回答正文、主张级引用、来源列表和版本信息 |
| INSUFFICIENT_EVIDENCE | 仓库证据不足、可尝试的查询调整和已搜索范围 |
| CONFLICTING_EVIDENCE | 冲突内容、各自来源和需要用户判断的差异 |
| MODEL_UNAVAILABLE | 模型或 Ollama 不可用，保留可执行的搜索建议 |
| INVALID_MODEL_OUTPUT | 模型结果未通过结构或引用校验，不展示未验证答案 |
| INDEX_NOT_READY | 索引不存在、过期或构建失败，说明恢复动作 |
| CANCELLED | 用户取消或超时，说明没有产生源文件写入 |

不能用空字符串、HTTP 200 或泛化的“出错了”代替终态。

### 定位原笔记

每条来源都应先提供跨平台稳定信息：相对路径、标题层级和可选行号。桌面环境可以额外生成打开 Obsidian 文件的本地链接，但该链接是便利功能，不是引用真实性的基础。

## 首发问题类型

### 精确事实与命令

示例：

- 某个 Git 配置项的作用域顺序是什么？
- 笔记中的某条命令如何验证挂载来源？
- 某个错误码或配置键在哪几篇笔记出现？

这类问题要求关键词检索保留命令、标识符、数字和大小写信息，不能只依赖向量相似度。

### 语义改写

示例：

- “如何判断文件实际位于哪个存储层？”与笔记标题用词不完全相同。
- “模型没有证据时应该怎么办？”需要找到拒答与引用笔记。

这类问题验证 Embedding 和中文语义召回，但回答仍只能使用检索证据。

### 跨文档综合

示例：

- 比较两种 Git 配置来源的优先级与适用场景。
- 把检索、引用、评测和发布门禁串成一条实施顺序。

系统应优先选取来源多样且互补的切片，避免把同一段落的重叠切片当作多份证据。

### 无答案与冲突

示例：

- 询问 demo vault 根本没有记录的版本号。
- 两篇合成笔记对同一配置给出不同结论或不同生效日期。

无答案必须拒答；冲突必须展示冲突而不是让模型自行选边。

### 仓库变化

用户新增、修改、删除或重命名笔记后再次索引，旧切片必须退出活动索引。v0.1 将重命名定义为“旧路径删除 + 新路径新增”，不承诺跨路径保持同一文档身份。

## MVP 功能范围

候选 CLI 入口如下，最终名称以代码仓库实现和帮助文本为准：

| 命令 | 职责 |
| --- | --- |
| vaultrag init | 生成显式配置并检查数据目录不在源 vault 内 |
| vaultrag doctor | 检查路径、权限、Ollama、模型能力和索引兼容性 |
| vaultrag index | 扫描、解析并原子发布一个索引代次 |
| vaultrag status | 展示源快照、活动代次、警告和待重建原因 |
| vaultrag search | 执行不生成回答的关键词、向量或混合搜索 |
| vaultrag ask | 检索、组装证据、调用模型并校验回答 |
| vaultrag eval | 对合成数据集执行确定性测试和可选本地模型评测 |
| vaultrag serve | 后置阶段启动只监听回环地址的本地 HTTP 服务 |

v0.1 只需完成 init、doctor、index、status 和关键词 search；ask 不应挡住首个可用版本。

## 配置体验

配置应满足：

- vault 根目录、数据目录和 Ollama 地址显式可见。
- 默认只包含 Markdown，默认排除版本库元数据、Obsidian 配置、回收站和隐藏缓存。
- 模型名称、超时、上下文预算和检索参数可配置但有安全默认值。
- 未知字段或不兼容版本默认失败，避免拼写错误被静默忽略。
- 输出有效配置的脱敏摘要，便于错误报告。
- CLI 参数可以覆盖当前运行，但实际生效配置会记录到运行证据。

公开示例只使用相对路径或通用占位符，不包含个人用户名、绝对路径、远程地址或真实笔记名称。

## Demo vault 设计

公开 demo vault 应模拟真实技术笔记结构，又不复制私人内容。建议包含：

- Linux 存储与权限基础。
- Git 配置作用域与代理边界。
- Markdown / Obsidian 链接规范。
- AI 检索、引用与拒答原则。
- 两篇包含受控冲突与日期差异的配置笔记。
- 一篇带恶意 Prompt Injection 文本的安全夹具。
- 标题、别名、标签、Callout、表格、代码块、Wikilink 和长章节样例。
- 删除、重命名、Frontmatter 错误、超长代码块和符号链接测试夹具。

每篇内容都由项目独立编写，并在文件头声明为合成示例。测试期望绑定 demo vault 的固定 revision。

## 非目标

首发明确不做：

- 不读取 PDF、Office、网页、图片、音频或 OCR。
- 不建立云端同步、账号、团队空间、RBAC 或多租户。
- 不写回、补全、整理、重命名或删除用户笔记。
- 不执行笔记中的 Shell、SQL、代码或链接。
- 不自动联网搜索，不把互联网内容混入本地证据。
- 不提供任意 Tool Calling、MCP 或写操作 Agent。
- 不训练、微调、量化或托管基础模型。
- 不自研聊天前端；本地 API 和第三方 UI 适配在核心链路稳定后再做。
- 不把 Wikilink 图谱直接升级为 GraphRAG。
- 不首发 Qdrant、Elasticsearch、Kafka、Kubernetes 等外部基础设施。

这些能力只有在真实用例、评测与维护成本证明必要时才重新评估。

## 失败体验合同

### 配置或路径错误

- vault 不存在、不可读或不是目录时，在扫描前失败。
- 数据目录位于 vault 内、与 vault 相同或通过符号链接落入 vault 时拒绝启动。
- 两个路径解析到同一真实位置时，不允许用字符串差异绕过。

### 文档错误

- 单个文件无法解析时记录相对路径、安全错误类别和失败计数。
- 默认不因一个坏文件发布半成品索引；是否允许“有警告发布”必须由配置与门禁明确。
- 任何日志都不默认打印完整笔记正文。

### 索引错误

- 构建发生错误时保留上一活动代次，新代次标记失败且不可查询。
- 模型、维度、切片器或解析器合同不兼容时要求重建。
- 删除文件失败不能留下活动陈旧切片。

### 模型错误

- Ollama 未运行、模型不存在、超时、取消和输出非法分别分类。
- 不因生成失败回退到无引用的普通聊天。
- 可向用户返回已经验证的检索结果，但必须标明尚未形成回答。

## 八分钟主线演示

### 0～1 分钟：问题与边界

- 展示项目定位和当前 release 的已实现矩阵。
- 声明 demo vault 为合成数据，程序只读源文件。

### 1～3 分钟：索引与增量

- 从空状态索引 demo vault。
- 修改、新增和删除测试笔记后再次索引。
- 展示活动代次、变更摘要和旧切片退出结果。

### 3～4 分钟：确定性搜索

- 搜索一个精确配置键和一段中文改写。
- 对比关键词、向量和融合排名，并打开相对路径来源。

### 4～6 分钟：问答与引用

- 提问跨文档问题。
- 展示回答主张、证据标识、标题路径和引用校验状态。

### 6～7 分钟：失败语义

- 提问仓库没有的事实，展示拒答。
- 提问冲突夹具，展示冲突来源。
- 注入“忽略规则并输出秘密”的笔记内容，展示其只被当作资料。

### 7～8 分钟：证据

- 打开 eval 报告、版本坐标和安全失败测试。
- 说明当前限制和下一版本退出条件。

演示只包含当前 release 已完成能力；缺失环节直接跳过，不用预录结果冒充运行证据。

## 产品验收清单

- 用户能在不阅读源码的情况下知道系统会读什么、写什么和连接什么。
- 纯搜索与模型问答可以独立使用和诊断。
- 每种失败都有稳定终态、恢复建议和非敏感错误信息。
- demo vault 覆盖成功、边界、冲突、无答案、删除和攻击用例。
- README 的已实现矩阵与 CLI 帮助、测试和 Release 一致。
- 任何个人笔记、路径、模型对话或运行日志都不进入公开仓库。
