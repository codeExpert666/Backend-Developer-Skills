本文定义 VaultRAG 如何在不修改源仓库的前提下发现、读取、解析和切分 Markdown，并把新增、修改、删除和配置变化发布为一致的索引代次。

源身份与代次模型见 [[VaultRAG 领域模型与数据契约]]，安全路径边界见 [[VaultRAG 安全、隐私与只读边界]]。

> [!note] 状态说明
> 下文是待实现算法与验收合同。具体 Markdown 库和存储库需通过技术验证后确定。

## 摄取目标

- 对同一源版本和配置产生确定性切片。
- 保留技术笔记中的标题层级、代码、列表、表格和 Callout 语义。
- 识别 Obsidian Frontmatter、Wikilink、嵌入链接与块标识，但不执行或递归展开内容。
- 用文件内容散列判断变化，不把修改时间当作权威事实。
- 正确撤销删除和重命名后的旧切片。
- 构建失败时继续提供上一完整代次。
- 对每个跳过、降级和失败文件给出可统计原因。

## 文件发现

### 根目录确认

索引前按以下顺序处理：

1. 解析用户配置的 vaultRoot 为绝对规范路径。
2. 确认路径存在、是目录并可读取。
3. 解析 dataDir 的真实路径及最近存在父目录。
4. 拒绝 dataDir 等于、位于或通过符号链接落入 vaultRoot。
5. 建立只读扫描上下文并记录根目录本地 fingerprint。

错误信息可以显示用户已输入路径，但持久日志和公开报告只保存安全摘要。

### 默认发现规则

- 只包含普通 UTF-8 Markdown 文件。
- 默认忽略 .git、.obsidian、.trash、派生数据目录和已配置隐藏缓存。
- 目录遍历顺序按规范化相对路径排序，保证报告与测试稳定。
- 默认不跟随符号链接。
- 显式开启符号链接时，真实目标必须仍在 vaultRoot 内；否则跳过并记录 SYMLINK_ESCAPE。
- 文件大小、数量和目录深度设置可配置上限，防止意外扫描巨大树。

排除规则作用于规范化相对路径；规则冲突和未知语法在扫描前失败。

## 源字节与编码

- v0.x 只接受 UTF-8；带 UTF-8 BOM 时统一移除后解析并记录。
- 无效 UTF-8 默认标记 FAILED，不用系统区域编码猜测。
- sourceHash 对原始文件字节计算，保证变化判断不受解析库影响。
- 换行规范化只发生在解析内存中，不改写文件。
- 空文件可以成为有效文档但不产生可检索切片。
- 二进制探测命中时跳过并记录，不把乱码发送给 Embedding 或模型。

## Markdown 中立结构

MarkdownParser 输出项目自己的 DocumentAST 或等价中立结构，而不是把第三方库节点泄漏给应用层。至少表达：

- Frontmatter 原始范围、解析字段和警告。
- 标题级别、文本、起止行和层级路径。
- 普通段落、列表、引用、表格与分隔线。
- Fenced Code Block 的语言、内容和范围。
- Obsidian Callout 的类型、标题和正文。
- Wikilink 的目标、显示文本、标题锚点与块标识。
- 嵌入链接与普通链接的类型差异。
- HTML 块是否保留文本或跳过的显式策略。

解析器不得访问网络、执行 HTML、读取链接目标或解释代码。

## Frontmatter 策略

项目只消费与检索相关的安全字段：

| 字段 | 用途 |
| --- | --- |
| title | 显示标题与检索字段 |
| aliases | 关键词召回与别名定位 |
| tags | 过滤与低权重检索字段 |
| created / updated | 来源展示与冲突提示，不作为真实性证明 |

规则：

- 缺少 Frontmatter 不阻止索引，标题回退到首个一级标题或文件名。
- YAML 边界完整但字段解析失败时，正文仍可进入 DEGRADED 版本，元数据警告可见。
- 未闭合 Frontmatter 不能静默吞掉全文；按固定恢复策略处理并进入失败夹具。
- 未知字段默认不送入 Prompt，避免秘密或大块数据泄漏。
- tags 的字符串与列表形式统一为规范化集合，但保留原文用于诊断散列。

## Obsidian 语义

### Wikilink

对 Wiki 链接解析以下形式：

- 文档目标。
- 文档加标题。
- 当前文档标题。
- 显示别名。
- 块标识。

解析结果用于元数据、定位和未来候选扩展，不在 v0.x 自动把目标正文拼入当前切片。这样可以避免循环、重复索引、权限扩大和上下文失控。

### 嵌入内容

嵌入形式只记录引用关系，不展开图片、PDF、Canvas 或另一篇笔记。Markdown 文档嵌入也不递归内联；用户需要相关内容时由检索独立召回。

### Callout

Callout 保留类型和标题，例如警告、提示或重要说明。类型可以作为低权重元数据，但不能把某种视觉样式直接当作事实优先级。

### 链接解析歧义

同名文件、别名冲突或标题不存在时记录解析状态。引用真实性仍依赖相对路径和源版本，不依赖 Obsidian 当前的模糊链接解析设置。

## 标题感知切片

### 基本单元

优先以标题章节为语义单元。每个切片带完整 headingPath，使模型看到“这段内容属于什么问题”，也让引用可以定位。

候选算法：

1. 按标题构建章节树。
2. 将章节开头的短引导与其首个子块保持相邻。
3. 将段落、列表、表格、Callout 和代码块视为不可随意截断的块。
4. 在目标 Token 预算内依次装箱。
5. 超过最大预算时，在块级安全边界继续拆分。
6. 为相邻切片加入少量语义重叠，但不重复整段长代码。
7. 写入起止行、标题路径、序号和内容散列。

初始目标可设为约 350～700 Token、硬上限约 1000 Token、重叠约 10%，但这些数值是评测候选，不是通用最佳值。应通过 [[VaultRAG 质量评测与发布门禁]] 的检索与上下文实验校准。

### 代码块

技术笔记中的代码不能默认丢弃：

- 短代码块与前后解释尽量保留在同一切片。
- 超长代码块按行或语法安全边界拆分，记录原语言和连续序号。
- 代码中的精确标识符进入关键词索引。
- 向量文本可以加入标题和语言前缀，但原始代码仍保留为引用内容。
- 任何代码都只作为数据，不执行、不格式化回写。

### 表格与列表

- 小表格保持完整并带表头。
- 大表格重复必要表头后按行组拆分。
- 有序步骤尽量不跨切片；必须拆分时保留起始序号和上下文。
- 纯导航目录可以降低正文权重，但不能用启发式直接删除而无诊断。

## 增量变化判定

每次扫描都对纳入范围的 Markdown 计算内容散列。对于个人规模 vault，优先正确性而不是依赖修改时间跳过散列。

| 变化 | 判定 | 行为 |
| --- | --- | --- |
| 未变化 | 同 relativePath、同 sourceHash、同解析与切片合同 | 复用 DocumentRevision、Chunk 与兼容 Embedding |
| 修改 | 同 relativePath、sourceHash 变化 | 新 Revision，重建其切片，按内容散列复用相同向量 |
| 新增 | 新 relativePath | 新 SourceDocument 与 Revision |
| 删除 | 上一快照存在、当前不存在 | 标记 SourceDocument 删除，新代次撤销全部索引项 |
| 重命名 | 旧路径删除、新路径新增 | 不做相似度身份推断 |
| 解析合同变化 | parserVersion 或 chunkerVersion 变化 | 全量重建切片 |
| Embedding 变化 | 模型、维度或规范化变化 | 保留可兼容文本投影，重建全部向量 |
| 关键词分析器变化 | tokenizer、字段权重或 Schema 变化 | 重建关键词索引 |

修改时间和大小只用于状态展示与未来可选优化。若以后增加快速模式，必须有定期全散列校验和显式风险说明。

## Embedding 缓存键

可复用向量的完整键至少包含：

- chunk contentHash。
- embedding provider 类型。
- 模型完整标识。
- 向量维度。
- 输入前缀或模板版本。
- 归一化策略。

任一字段变化都不能复用旧向量。缓存命中后仍校验维度和有限数值，拒绝 NaN、Inf 或长度错误。

## 原子构建流程

~~~text
scan source bytes
  -> create complete VaultSnapshot
  -> parse changed revisions
  -> produce deterministic chunks
  -> write staging metadata
  -> update staging lexical index
  -> reuse or generate vectors
  -> update staging vector index
  -> validate counts, identities and dimensions
  -> mark generation READY
  -> atomically switch ACTIVE generation
  -> retire previous generation
~~~

任何中间错误：

- 标记当前构建 FAILED 或 CANCELLED。
- 保留上一 ACTIVE 代次。
- 不把暂存索引暴露给查询。
- 输出恢复建议和安全摘要。
- 在后续清理中只删除明确识别的失败 generation 目录。

## 一致性校验

激活前至少检查：

- READY snapshot 中每个 ACTIVE SourceDocument 都有当前 Revision。
- 每个可检索 Chunk 都指向当前 Revision。
- 关键词与向量条目只引用暂存 generation 的活动 Chunk。
- 要求向量的 Chunk 数与成功向量数一致；允许降级时策略必须显式。
- 向量维度与 embeddingProfile 完全一致。
- 删除文档在新索引中无残留。
- Manifest 计数与实际索引计数一致。
- 相对路径无法逃逸 vaultRoot。
- dataDir 仍不位于 vault 内。

## 失败策略

| 失败 | 默认行为 |
| --- | --- |
| 单文件不可读 | 构建失败；用户修复权限或排除该文件 |
| Markdown 局部语法异常 | 按解析器规则降级并记录，是否发布由严格模式决定 |
| Frontmatter 元数据异常 | 正文可降级索引，字段不进入过滤 |
| 文件在扫描中变化 | 重读并重新散列；超过重试上限则构建失败 |
| Ollama / Embedding 不可用 | 关键词代次可按明确模式发布；混合代次不得伪装完整 |
| 向量维度变化 | 立即失败并要求重建 |
| 磁盘空间不足 | 保留旧代次，失败暂存区可安全清理 |
| 用户取消 | 停止 Worker，标记 CANCELLED，不激活 |
| 进程崩溃 | 下次启动识别未完成 generation，不将其当作活动索引 |

“允许有警告发布”必须在报告中显示 DEGRADED，不能把失败文件计入成功。

## 测试夹具

摄取测试至少覆盖：

- 空 vault、空文件和只有 Frontmatter 的文件。
- 中英文标题、Emoji、组合 Unicode、空格和大小写路径。
- 合法与非法 Frontmatter、重复别名和多种 tags 形式。
- 深层标题、无一级标题、跳级标题和重复标题。
- 嵌套列表、Callout、表格、引用、HTML 与超长段落。
- 带反引号内容、不同语言代码块和未闭合代码围栏。
- 普通 Wikilink、标题链接、别名、块标识、嵌入、同名与坏链接。
- 新增、修改、删除、重命名、扫描中变化和连续取消。
- 符号链接到 vault 内、vault 外、循环与断链。
- 大文件、深目录、无效 UTF-8 和疑似二进制。
- 解析器、切片器、关键词和 Embedding 合同升级。

这些夹具全部来自合成 demo vault 或测试资源，不能复制私人仓库内容。

## 验收标准

- 同一输入、配置和版本连续构建，Chunk 身份与内容完全一致。
- 修改一个文件只重建必要 Revision，未变内容可安全复用向量。
- 删除和重命名后旧内容无法被 search 或 ask 找到。
- 构建失败、取消或崩溃后上一活动代次仍可查询。
- 所有路径、跳过、失败和降级都有机器可读类别。
- 源 vault 在完整与增量构建前后字节散列集合保持不变。
- 私人正文不会出现在默认日志与公开报告中。
