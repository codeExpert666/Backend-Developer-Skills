本文定义 VaultRAG 如何从用户问题得到可验证 Evidence，以及回答如何定位回当前源版本。通用方法见 [[关键词、向量与混合检索及评测]] 与 [[RAG 的证据链、引用与质量评测]]。

> [!note] 状态说明
> 检索参数、阈值和索引实现都需要用合成评测集校准。这里确定的是管线、数据边界和失败语义，不宣称当前已有质量结果。

## 为什么必须混合检索

中文技术笔记同时包含两类信息：

- 自然语言概念、同义表达和跨标题描述，适合语义向量召回。
- 命令、文件名、错误码、配置键、数字和缩写，适合关键词精确召回。

只用向量可能漏掉精确标识符；只用关键词可能找不到语义改写。VaultRAG 因此并行执行关键词和向量召回，再由确定性融合得到候选。

混合检索不是把两个分数直接相加。不同检索器的分数尺度可能完全不同，必须采用排名融合或经过评测的归一化。

## 检索管线

~~~mermaid
flowchart LR
    Q["原始问题"] --> N["受控规范化"]
    N --> L["关键词召回"]
    N --> E["查询 Embedding"]
    E --> V["向量召回"]
    L --> F["排名融合"]
    V --> F
    F --> D["去重与来源多样性"]
    D --> X["邻接扩展"]
    X --> B["证据预算与组装"]
    B --> C["Evidence 候选集"]
~~~

每一步都记录版本、参数、数量和耗时；原始私人问题是否持久化由隐私配置决定。

## 查询规范化

允许的确定性处理：

- Unicode 和空白规范化。
- 识别引号内精确短语。
- 保留大小写敏感候选与小写检索副本。
- 提取配置键、路径片段、命令、错误码、版本和数字特征。
- 解析显式路径或标签过滤器。
- 对中文与英文混合文本采用固定 tokenizer 策略。

默认不做：

- 不用大模型改写后替换原始问题。
- 不删除否定词、符号或版本号。
- 不根据历史对话暗中扩大 vault 范围。
- 不把用户文本解释为 Shell、SQL、正则或文件路径操作。

后续若增加查询扩展，必须保留原查询并评测扩展是否引入错误召回。

## 关键词索引

候选字段及初始权重方向：

| 字段 | 作用 |
| --- | --- |
| title / aliases | 精确主题与常用名称，高权重 |
| headingPath | 章节语义，高权重 |
| body | 主要正文 |
| code | 配置键、命令和错误文本，使用适合标识符的分析策略 |
| tags | 过滤与低权重补充 |
| relativePath | 显式路径查询，不作为普通语义主要来源 |

实现必须验证：

- 中文词与连续短语。
- 驼峰、蛇形、点分配置键和带短横线命令。
- 大小写、数字、版本和标点。
- 标题命中与正文多次重复的权重关系。
- 停用词不会删除技术关键字。

关键词命中返回 rank、字段和受控命中解释，不向领域层泄漏具体库对象。

## 向量召回

- 文档向量输入由标题路径、必要元数据和切片正文组成，模板版本化。
- 查询向量使用与文档相同模型、维度和兼容前缀合同。
- 所有向量在写入和查询时校验维度与有限数值。
- 相似度函数和归一化策略属于 embeddingProfile。
- 更换模型、维度或输入模板必须重建，不混用旧向量。
- Embedding 失败不会自动使用零向量。

向量索引只保存派生表示和定位标识，不能替代源切片。

## 排名融合

初始候选采用 Reciprocal Rank Fusion，因为它只依赖各检索器内部排名：

~~~text
rrfScore(document) = sum(1 / (k + rank_i(document)))
~~~

k 的初始候选值可从 60 开始，但必须在 eval 中比较，不作为未经验证的最佳参数。每个检索器先取受控 Top-N，再融合。

融合结果记录：

- lexicalRank 与 vectorRank。
- 各通道是否命中。
- rrfScore。
- 使用的 k、Top-N 与索引版本。
- 被去重、过滤或多样性规则移除的原因。

如果向量服务不可用，系统可明确降级为 LEXICAL 模式；结果状态和报告必须显示降级，不能仍标记为完整 HYBRID。

## 去重与多样性

### 重叠切片

同一文档相邻切片可能因 overlap 重复。组装证据前：

- 按 sourceId、revisionId 和行范围计算重叠。
- 保留信息更完整或排名更高的切片。
- 必要时合并相邻连续片段，但重新计算 Token 和引用范围。
- 不把两个高度重叠片段统计成独立来源支持。

### 来源多样性

跨文档问题需要避免 Top-K 被一篇长笔记占满。候选策略：

- 每个 SourceDocument 设置软上限。
- 先保证高相关来源，再增加互补来源。
- 标题和路径相同的镜像内容按内容散列降权。
- 多样性只能在相关性候选内工作，不能为凑文档数加入无关证据。

### 邻接扩展

当命中切片缺少定义、步骤上下文或代码解释时，可以加入同一 Revision 的前后相邻切片。扩展片段必须：

- 明确标记为 neighbor，不伪装原始命中。
- 仍受总证据预算限制。
- 与命中片段共享标题路径或满足明确章节规则。
- 使用自己的 chunkId 和引用范围。

## 证据充分性

“Top-K 非空”不等于足以回答。应用层在生成前进行候选判断：

- 是否至少有一个达到校准标准的直接证据。
- 问题包含多个子项时，证据是否覆盖关键子项。
- 是否只有目录、导航、定义片段或代码而缺少解释。
- 是否存在同一事实的明显冲突。
- 是否因过滤器、索引降级或上下文预算截断了关键来源。

初期不要凭感觉设置一个通用相似度阈值。阈值和规则按问题类别、检索模式与固定评测校准，并保存版本。

证据明显不足时直接返回 INSUFFICIENT_EVIDENCE，不调用模型以期待它“补全”。

## Evidence 组装

发送给模型的每条 Evidence 使用应用生成格式：

~~~text
[E1]
source: Git/安装与配置
heading: 配置来源 > 作用域优先级
revision: short-hash
content:
受控切片正文
~~~

公开示例使用合成路径。真实运行可在进程内使用相对路径，但默认不把私人路径或正文写入持久日志。

组装顺序考虑：

- 直接相关性。
- 子问题覆盖。
- 来源多样性。
- 标题定义与正文说明的顺序。
- 上下文 Token 预算。

模型看到 evidenceId、内容和最小定位信息；最终展示用路径、行号和版本由应用从 Evidence 恢复，不采用模型输出的路径字符串。

## 主张级引用合同

回答不只在末尾附一串“参考资料”。结构化候选应把每个可核查主张关联 evidenceIds。

程序依次检查：

1. evidenceId 属于当前 RetrievalRun。
2. Evidence 属于固定 generationId。
3. SourceDocument 和 Revision 仍是该代次活动内容。
4. 至少一个证据支持该主张的主要事实。
5. 路径、标题和行号由应用渲染。

前三项完全确定性；第四项可用规则、专门评测与人工抽样组合，不能只让同一个生成模型自评。

无引用的一般性过渡语可以保留，但命令、数值、配置结论、因果判断和仓库内容摘要必须有引用。

## 引用定位

跨平台稳定引用由以下字段组成：

- vault 内相对路径。
- headingPath。
- startLine / endLine。
- source revision 短散列。

CLI 首先输出这些字段。桌面适配器可额外生成：

- 打开 Obsidian 文档的标准本地 URI。
- 打开默认编辑器或文件管理器的动作。

定位动作只接受已验证 SourceDocument，不拼接模型给出的路径。标题定位不受标准 URI 支持时，仍可通过相对路径和 headingPath 手动核对。

## 冲突与时效

笔记可能在不同时间给出不同结论。检索阶段识别候选信号：

- 同一配置键或主张出现互斥值。
- 来源带不同 updated 或显式生效日期。
- 标题包含废弃、旧版、迁移、当前等时效词。
- 一篇文档引用另一篇但结论不一致。

模型不能静默决定哪个来源“更权威”。若无法由明确项目规则消解，返回 CONFLICTING_EVIDENCE，并并列展示来源、版本和差异。

Frontmatter updated 只是作者元数据，不证明内容真实；Git revision 和当前源散列用于可追踪，不提供外部真实性。

## 检索可观测字段

每次运行至少记录摘要：

- generationId 与 query fingerprint。
- 模式、过滤器和候选上限。
- 关键词、向量、融合、去重和最终数量。
- 各阶段耗时与降级原因。
- Evidence 的 sourceId、chunkId 和排名信号。
- 上下文使用量与被截断原因。

默认不记录完整问题、Evidence 正文或答案正文。运行质量原则见 [[AI 应用的成本、延迟、可观测性与降级]]。

## 评测矩阵

| 类别 | 主要检查 |
| --- | --- |
| 精确标识符 | 配置键、命令、错误码和版本是否进入 Top-K |
| 中文改写 | 不同词表达的概念是否召回正确章节 |
| 跨文档 | 多个必需来源是否都被召回 |
| 代码与解释 | 代码片段及其说明是否共同进入证据 |
| 无答案 | 无关高相似内容是否被正确拒绝 |
| 冲突 | 互斥来源是否同时保留并触发冲突 |
| 删除与更新 | 旧 Revision 是否完全退出搜索 |
| 注入内容 | 恶意文本是否只作为证据数据处理 |
| 降级 | 向量不可用时关键词结果和状态是否正确 |

详细指标和发布门槛见 [[VaultRAG 质量评测与发布门禁]]。

## 验收标准

- search 可以独立展示关键词、向量与融合结果。
- 精确标识符不会因中文分词或语义检索而不可查。
- 同一查询、代次和参数的确定性阶段结果稳定。
- 删除或更新后的旧切片不出现在任何召回通道。
- 模型不能引用候选 Evidence 之外的文件或切片。
- 无答案与冲突有独立终态，不被强行生成回答。
- 所有质量数字绑定固定 eval、代码 revision、索引与模型坐标。
