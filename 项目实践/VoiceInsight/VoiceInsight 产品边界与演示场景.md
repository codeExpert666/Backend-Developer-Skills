本文定义 VoiceInsight 的用户、业务对象、核心场景、MVP 范围、演示数据和验收故事。它只描述产品语义，不提前冻结 HTTP 路径、Java 类、Go 包或数据库表名。

本文是候选产品设计，不代表功能已经实现。项目定位与真实性边界见 [[VoiceInsight 项目实践总览]]。

## 要解决的问题

用户反馈通常来自热线、应用内反馈、Beta 测试、问卷、客服工单或人工整理文件。原始数据存在五类困难：

1. 来源、字段、时间和附件格式不一致，导入失败时难以解释和恢复。
2. 产品与特性分类依赖人工经验，同一问题可能被不同人员归入不同类别。
3. NPS、NSS、问题数量和趋势经常由临时 SQL 计算，口径、权限和样本范围不透明。
4. 图表能展示数据，却不能快速回答“为什么变化”“证据是什么”“下一步看什么”。
5. AI 可以帮助理解文本，但如果直接接触数据库、权限和发布动作，会引入越权、幻觉和不可追溯风险。

VoiceInsight 的产品闭环是：

```mermaid
flowchart LR
    S["多来源原始数据"] --> I["导入、校验与来源追踪"]
    I --> D["统一反馈与问卷模型"]
    D --> C["分类、审核与特性映射"]
    C --> A["指标、趋势与证据查询"]
    A --> R["报告草稿与异常告警"]
    A --> G["自然语言分析与只读 Agent"]
```

任何后续能力都不能绕过前面的数据质量和来源追踪。

## 目标用户与权限意图

| 角色 | 主要目标 | 默认数据范围 | 高风险操作 |
| --- | --- | --- | --- |
| 平台管理员 | 管理账号、角色、产品范围和基础配置 | 全部产品，但仍受审计 | 权限变更、数据删除、口径启停 |
| 产品负责人 | 查看负责产品的反馈、指标、报告和告警 | 被授权产品及其特性 | 发布报告、修改告警规则 |
| 数据分析人员 | 导入、清洗、分类、复核和分析数据 | 被授权产品，可按职责细分写权限 | 批量导入、接受 AI 分类结果 |
| 数据上传人员 | 提交文件并查看自己批次的处理结果 | 指定产品和来源 | 取消批次、重新提交 |
| 审计或只读人员 | 核对计算口径、来源和操作记录 | 明确授权范围 | 无业务写权限 |

平台不信任客户端或模型提交的 `userId`、角色、产品列表。身份和数据范围由服务端认证上下文解析，并在查询、检索和工具执行的每一层强制应用。

## 虚构业务对象

公开演示不得使用真实公司、部门或产品名称。建议使用以下虚构产品线：

- `Orion Auto`：车载系统。
- `Nova Watch`：穿戴设备。
- `Halo Glasses`：智能眼镜。
- `Motion App`：运动健康应用。

每个产品有版本、地区和分层特性，例如连接、续航、通知、导航、运动记录和隐私。特性树与分类口径必须版本化，因为产品迭代会新增、合并或废弃特性。

## 核心数据来源

| 来源类型 | 主要内容 | 首版接入方式 | 风险边界 |
| --- | --- | --- | --- |
| 市场反馈 | 文本描述、渠道、时间、产品版本、可选附件 | CSV / Excel / JSON 导入 | 文本可能含个人信息和恶意指令 |
| Beta 问题 | 结构化问题、严重度、复现信息、附件元数据 | CSV / Excel 与合成附件 | 不导入真实内部日志、图片或视频 |
| 问卷 | 推荐意愿、特性评分、产品和时间 | CSV / Excel | 量表和缺失值规则必须随批次保存 |
| 连接器事件 | 公开许可 API、Webhook 或合成源 | Go 连接器 | 遵守授权、速率限制和删除要求 |

首版不实现对任意网站的通用爬虫。只有来源提供公开许可或明确授权的 API 时，才新增对应连接器；`robots.txt`、服务条款、认证和限流是进入条件，不是上线后的补救项。

## 第一条端到端演示故事

一个产品负责人只能访问 `Nova Watch`。数据分析人员上传一份包含反馈和问卷的合成数据包：

1. 平台创建导入任务并返回上传要求。
2. 文件校验发现两行缺少产品版本、一行评分越界；批次显示可定位错误，不把部分失败伪装为全部成功。
3. 修正后重新提交，平台以稳定幂等键避免重复写入已接收记录。
4. 产品负责人查看最近两个月的 NPS 趋势、Top 问题和支持这些结论的反馈样本。
5. 无权访问 `Orion Auto` 的用户请求该产品数据，HTTP API、搜索层和 Agent 工具都返回一致的权限拒绝。
6. AI 为未分类反馈生成结构化“问题类别 + 特性候选 + 证据片段”，低置信或未知类别进入人工复核，不自动覆盖人工标签。
7. 用户询问“最近两个月 Nova Watch 的 Top 市场问题是什么”，系统把问题转换成受限分析参数，调用确定性查询工具并返回样本量、时间范围、计算时间和证据链接。
8. 定时任务生成周报草稿；数值与图表来自确定性聚合，模型只撰写有引用的文字摘要。报告经人工确认后才发布。

这条故事同时覆盖数据治理、权限、查询、指标、异步处理、AI 和审计，是各阶段共同的回归主线。

## 反馈与问卷的产品语义

### 反馈记录

一条反馈至少能回答：

- 来自哪个来源和原始记录。
- 属于哪个产品、版本、地区和时间范围。
- 原始文本与规范化文本分别是什么。
- 当前人工分类、AI 候选分类及其版本是什么。
- 是否包含附件，附件能否安全读取。
- 谁在何时修改、复核或归档了它。

原始文本与清洗结果不能互相覆盖。清洗、脱敏和分类都是可追溯的派生结果。

### Beta 问题

Beta 问题可以复用反馈主模型，但保留严重度、状态、复现信息和来源编号等差异字段。项目不把它扩展成完整缺陷管理系统；问题分派、代码提交关联和发布管理不在主线。

### 问卷与评分口径

NPS 常见定义把推荐者、被动者和贬损者按评分区间划分，但实际来源可能采用不同最小分值。VoiceInsight 不把某个区间硬编码到 SQL，而是保存评分方案：

- 最小分、最大分。
- 推荐者起始分。
- 贬损者截止分。
- 缺失、无效和不适用答案的处理规则。
- 方案版本、生效时间和来源说明。

在某一方案下：

$$
NPS = \frac{推荐者数量 - 贬损者数量}{有效回答数量} \times 100\%
$$

`NSS` 在不同组织中可能代表不同的特性满意度口径，因此它是“项目自定义指标”，必须同样版本化名称、公式、评分区间和分母规则，不能把内部叫法描述成行业统一标准。

每个聚合响应至少返回 `metricDefinitionVersion`、有效样本数、过滤条件和计算时间，避免只有一个百分比而无法复核。

## MVP 与后续能力边界

### 可投递后端 MVP

- 用户认证、角色权限和产品数据范围。
- 产品、版本、特性树与来源管理。
- CSV / Excel / JSON 导入任务、校验错误、幂等重试和取消。
- 反馈、Beta 问题和问卷的查询与详情。
- 版本化 NPS / NSS 口径、趋势和 Top 问题聚合。
- 操作审计、结构化日志、数据库迁移和自动化测试。
- Docker Compose 本地运行、初始化合成数据和一键回归入口。

这个版本即使没有 Kafka、Elasticsearch 或 AI，也必须能够独立展示业务价值。

### 工程增强版本

- Go 连接器与批处理 Worker。
- Transactional Outbox、消息队列、重试、死信和可重放消费。
- Elasticsearch 全文与混合检索投影。
- 有使用证据的 Redis 缓存、限流或短期任务状态。
- OpenTelemetry 跨 Java、Go、消息和模型调用的 Trace。
- CI/CD、镜像扫描、备份恢复和故障演练。

### AI 增强版本

- 问题观点与产品特性的结构化分类候选。
- 报告文字草稿与证据引用。
- 文本证据的混合检索和 RAG。
- 受限自然语言分析工具。
- 有步骤、工具、成本和停止上限的只读 Agent。
- 后期可选的只读 MCP 适配面。

具体 AI 顺序与红线见 [[VoiceInsight AI 应用与受控 Agent 设计]]。

## 合成数据集设计

代码仓库建立后应生成三档可重复数据，而不是提交真实数据：

| 数据档位 | 用途 | 计划规模 | 必须覆盖 |
| --- | --- | --- | --- |
| `smoke` | 本地演示和端到端测试 | 数百条反馈与问卷 | 正常、无权、无答案、导入错误 |
| `integration` | 查询、索引、消息和 AI 回归 | 数千至数万条 | 多产品、多版本、口径变化、重复和冲突 |
| `load` | 性能与容量实验 | 按脚本参数生成 | 倾斜分布、热点特性、大文件和消费积压 |

数据生成器必须固定随机种子，并保存生成参数、Schema 版本和预期聚合结果。负载数据只作为本地或测试环境证据，不能伪装成真实生产规模。

文本样例需要包含：

- 直接提及特性的清晰问题。
- 同义表达、错别字、混合语言和含糊描述。
- 一条反馈涉及多个观点或多个特性。
- 不属于已知分类的内容。
- 含个人信息样式但由生成器虚构的内容，用于验证脱敏。
- 尝试诱导模型忽略规则、泄露数据或调用工具的提示注入文本。

## 数据保密与合规边界

- 只提交合成数据、公开许可数据和生成附件。
- 默认不把完整原始反馈、附件或个人信息发送给外部模型；实验前先最小化字段并完成脱敏。
- 原始附件按不可信文件处理，限制类型、大小、压缩层级、解压总量和读取超时。
- 表格导出防止公式注入；文件名和路径不能决定服务端真实存储路径。
- 删除、保留和重建规则需要覆盖 MySQL、对象存储、搜索投影、缓存和评测样本。
- 日志、Trace 和 Prompt 记录只保存定位所需摘要或散列，不保存密钥和无必要的全文。

## 产品验收问题

每次发布至少能够明确回答：

1. 这次分析使用了哪些产品、来源、时间和评分口径？
2. 结果能否回到原始记录和导入批次？
3. 无权限用户是否在数据库查询、搜索和 AI 工具三处都被拒绝？
4. 部分导入失败、重复提交和取消后，数据是否仍然一致？
5. 指标数值由哪段确定性代码计算，AI 是否只能解释而不能修改？
6. 搜索或模型不可用时，核心查询是否仍有明确降级或失败结果？
7. 一条告警为什么触发，基线、样本量和阈值是什么？
8. 简历上的每个数字能否由当前 revision 的脚本重新生成？

这些问题的自动化和证据要求见 [[VoiceInsight 工程质量、验证与交付标准]]。
