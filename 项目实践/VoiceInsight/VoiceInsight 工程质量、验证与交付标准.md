本文定义 VoiceInsight 从单个改动到可投递版本的质量、验证、观测、安全、性能、发布和恢复标准。它描述应建立的门禁，不代表当前已有测试或运行结果。

阶段顺序见 [[VoiceInsight 迭代实施路线图]]，AI 特有评测见 [[VoiceInsight AI 应用与受控 Agent 设计]]。

## 证据分层

以下结果不能互相替代：

| 证据层 | 能证明 | 不能证明 |
| --- | --- | --- |
| 静态解析与格式检查 | 文件、Schema 或代码满足基础语法与风格 | 业务行为正确 |
| 单元测试 | 局部规则和纯函数在固定输入下正确 | 真实数据库、网络和依赖行为 |
| 集成测试 | 组件与真实依赖在测试环境协作 | 完整用户链路、生产容量和恢复 |
| 契约测试 | 生产者与消费者理解同一接口或事件 | 业务数据和权限一定正确 |
| 端到端测试 | 一条部署链路可从入口走到结果 | 所有边界、负载和故障已覆盖 |
| 性能测试 | 指定硬件、数据和版本下的延迟、吞吐与资源 | 其他环境或生产规模 |
| 故障与恢复演练 | 指定故障下能按 Runbook 恢复 | 从未演练的组合故障 |
| AI 评测 | 固定数据和模型快照下的质量与安全表现 | 概率系统永远不会失败 |
| 公开演示 | 他人可以观察一条成功或失败链路 | 系统已在真实企业生产运行 |

简历和 README 必须说明使用的是哪一层证据。

## Definition of Done

一个业务能力只有同时满足适用项才算完成：

1. 产品目标、非目标、权限和失败语义已明确。
2. API、事件、数据库迁移和状态机与实现同步。
3. 正常、边界、权限、重复、取消和依赖失败有自动化测试。
4. 日志、指标和 Trace 能定位请求、任务、事件或模型调用。
5. 敏感字段、文件输入、秘密和导出已做安全审查。
6. 性能或容量敏感改动有基线、预算和回归结果。
7. 部署、回滚、数据迁移和恢复影响已评估。
8. 文档说明如何运行、验证、排障和重放。
9. CI 在干净环境通过，测试后没有未解释的工作树变化。
10. 任何跳过、未运行或环境受限检查均被明确记录。

只有代码编译通过或接口能返回 `200` 不算完成。

## 测试组合

### Java

| 类型 | 重点 |
| --- | --- |
| 单元测试 | 评分口径、状态机、权限组合、幂等冲突、日期与时区、错误映射 |
| 模块测试 | 模块公开 API、禁止依赖、模块事件和事务边界 |
| Web 测试 | 参数、认证、授权、序列化、Problem Details、分页与取消 |
| MySQL 集成 | Flyway、MyBatis 映射、事务、锁、索引、批量写和真实 SQL 行为 |
| Kafka 集成 | Outbox、生产、重复消费、位点、乱序、死信和重放 |
| Elasticsearch 集成 | 映射、过滤、版本冲突、别名切换、权限和重建 |
| 安全测试 | 数据范围、导出、文件上传、会话、秘密和审计 |

数据库、Kafka 和 Elasticsearch 关键测试使用 Testcontainers 或等价真实依赖，不用 H2 伪装 MySQL 行为。

### Go

| 类型 | 重点 |
| --- | --- |
| 表驱动单元测试 | 解析、校验、错误分类、退避、Manifest 和状态转换 |
| Fuzz | CSV、压缩包元数据、字符集、路径、事件和模型结构化输出 |
| Race Test | Worker 池、取消、共享状态、指标和优雅停机 |
| 集成测试 | 对象存储、Kafka、Java 内部 API 和重启恢复 |
| Benchmark / Profile | 大文件、批处理、内存分配、Goroutine 与网络并发 |
| Contract Test | OpenAPI 客户端、事件 Schema、错误与幂等语义 |

并发测试必须证明 Goroutine 随取消、超时或关机退出，不能只检查主函数返回。

### 端到端主线

每次可投递版本至少重放：

1. 初始化四个虚构产品、角色和数据范围。
2. 上传包含正常、错误和重复行的合成数据。
3. 观察导入任务到达正确终态并定位错误。
4. 查询 NPS / NSS、Top 问题与证据，核对固定期望值。
5. 用无权账号从 HTTP、搜索和 Agent 三条入口访问其他产品，全部被拒绝。
6. 在适用版本中重放消息、搜索、AI 分类、报告草稿和只读 Agent。
7. 停止一个依赖并验证降级、终态和恢复。

## 数据库与迁移门禁

- 所有结构和基础数据变更通过 Flyway，不接受 README 中的手工 SQL 作为唯一步骤。
- 新库从零迁移与上一发布版本升级都要测试。
- 已发布迁移不修改内容；错误通过新的前向修复迁移处理。
- 迁移前评估锁、扫描、回填、空间和回滚影响；大回填与 DDL 拆开。
- 索引增加前记录目标查询、数据分布和执行计划；增加后比较计划、延迟和写入成本。
- NPS / NSS 等指标使用固定 fixture 做差分测试，防止 SQL 优化改变分母或时间边界。
- 备份只有在恢复到隔离环境并完成一致性检查后才算可用。

## HTTP 与事件契约门禁

### OpenAPI

- OpenAPI 是客户端可见契约，路由、状态码、认证和响应必须与实际应用一致。
- CI 执行规范 Lint、生成或编译、真实 Router 覆盖和 breaking-change 比较。
- 分页、过滤、排序和时间范围使用受控枚举与上限，不接受 SQL 片段。
- 错误结构包含稳定业务代码、可定位请求 ID 和安全消息，不泄露堆栈或 SQL。
- 幂等请求明确 Key 作用域、保留时间、相同请求和冲突请求的响应。

### 事件

- 每个事件有 `eventId`、发生时间、Schema 版本、业务聚合标识与版本。
- 生产者测试生成的负载可以被当前及支持范围内的消费者解析。
- 新字段默认可选并有明确缺省语义；破坏性变化发布新主版本。
- 消费者不信任负载中的用户身份或权限，执行前重新读取必要权威事实。
- 大文件只传引用、大小与散列，不把完整反馈集塞入消息。

## 权限与安全门禁

### 身份和数据范围

- 区分认证、操作权限和产品数据范围。
- 允许与拒绝路径都测试；拒绝不能只存在于前端按钮。
- 缓存 Key、Elasticsearch 查询、导出任务、报告与 Agent 工具均包含或重新计算数据范围。
- 管理员也通过明确角色和审计工作，不在代码中用魔法账号绕过。
- 审计记录主体、动作、对象、结果和关联 ID，但不保存秘密和无必要正文。

### 文件与导入

- 校验扩展名、媒体类型、文件签名、大小、条目数和内容散列。
- 文件名不能直接成为服务端路径；拒绝绝对路径、父目录穿越和符号链接逃逸。
- 解压限制总大小、文件数、嵌套层级、单文件大小和处理时间。
- 表格导出转义以 `=`, `+`, `-`, `@` 等开头的危险单元格。
- 解析器进程或线程具有超时、内存和临时目录清理策略。

### Web 与服务

- 密码使用适合密码存储的自适应哈希；会话、Token、Cookie 与 CSRF 策略按实际客户端选择。
- CORS 只允许明确来源、方法和凭据组合。
- SQL 全部参数化；动态排序、分组和列名由服务端枚举映射。
- 外部连接器防 SSRF，只允许批准的 Scheme、主机和地址范围，并限制重定向。
- 秘密来自本地安全配置或部署 Secret，不进入镜像、仓库、日志和 Trace。
- 依赖、许可证、秘密、源代码和容器镜像扫描进入 CI；高风险发现有处理记录。

### AI

- 原始反馈和检索文档按不可信输入处理。
- 模型不提供可信身份、产品范围、确认状态和工具权限。
- 结构化输出后仍执行 Schema、业务和授权校验。
- Prompt、模型、工具和评测集版本可定位。
- 越权、提示注入、数据泄漏和虚构执行结果属于发布阻断项。

通用威胁模型见 [[AI 应用安全威胁建模与防护]]。

## 性能与容量验证

### 先定义工作负载

每次性能报告记录：

- 代码 revision、构建参数和依赖版本。
- CPU、内存、磁盘、操作系统和容器限制。
- fixture 种子、数据量、字段长度、产品分布和热点比例。
- 并发模型、预热、持续时间、请求组合和失败注入。
- P50、P95、P99、吞吐、错误率、超时、资源和依赖指标。
- 测试前后数据状态、瓶颈判断与改动收益。

没有环境和数据说明的“支持十万并发”或“性能提升 80%”不得出现。

### 分阶段性能场景

| 场景 | 关注指标 | 首要排查层 |
| --- | --- | --- |
| 单文件导入 | 行吞吐、峰值内存、错误定位时间 | 解析、批次大小、对象 I/O、MySQL 写入 |
| 多任务导入 | 队列等待、取消延迟、Goroutine、连接池 | 并发上限、背压、Kafka Lag |
| 反馈查询 | P95 / P99、扫描行数、排序与分页稳定 | SQL、索引、数据分布、缓存命中 |
| 指标聚合 | 时间区间、分组数量、临时表和 CPU | 查询计划、预聚合、读写隔离 |
| 搜索 | Recall、P95、过滤成本和索引新鲜度 | Mapping、分片、查询组合、权限过滤 |
| AI 分类 | 吞吐、429、Token、成本、重试和弃权 | 批次、限流、并发、模型与 Prompt |
| Agent | 首 Token、总时延、工具次数、成功终态 | 规划、检索、工具、模型和超时预算 |

性能预算在首个基线后确定并写入项目 ADR 或发布门禁。路线图不提前编造生产 SLO。

## 可观测性设计

### 关联标识

| 标识 | 生命周期 |
| --- | --- |
| `requestId` | 一次外部 HTTP 请求，可由服务端生成或校验后接受 |
| `traceId` | 跨 Java、Go、Kafka、搜索和模型调用的分布式 Trace |
| `importJobId` | 一次导入任务及其所有尝试 |
| `eventId` | 一条事件和重复消费判断 |
| `reportRunId` | 一次固定数据截止点的报告运行 |
| `aiRunId` | 一次分类、RAG 或 Agent 运行 |

业务日志使用结构化字段，不依赖在文本中搜索整段异常。敏感文本只记录长度、散列、类型或安全摘要。

### 最小指标

- HTTP：请求数、错误率、延迟分布、在途请求和拒绝数。
- MySQL：连接池、慢查询、事务时间、锁等待和失败。
- 导入：各状态任务数、行吞吐、失败类别、取消延迟和积压。
- Kafka：生产失败、消费速率、Lag、重试、死信和重复命中。
- Elasticsearch：查询延迟、拒绝、索引延迟、文档版本冲突和重建进度。
- AI：模型、Prompt 版本、最终状态、Token、成本、首 Token、总延迟、工具次数和弃权。
- 业务：有效反馈数、问卷样本量、报告运行和告警去重结果。

指标标签不能包含用户 ID、反馈全文、高基数字段或无限制错误消息。

### Trace 边界

- HTTP 入口创建或继续 Trace。
- Kafka 将上下文作为标准传播字段，而不是依赖线程本地状态。
- Go 从消息或请求恢复上下文，并传给对象存储、Java API 和模型调用。
- Java 异步执行显式传播安全主体和必要关联字段，不假设 MDC 或 SecurityContext 自动存在。
- Agent Trace 记录工具选择、参数的安全摘要、终态与引用，不保存隐含推理全文。

## CI 门禁顺序

```mermaid
flowchart LR
    F["格式与静态检查"] --> U["单元与模块测试"]
    U --> I["真实依赖集成测试"]
    I --> C["OpenAPI 与事件契约"]
    C --> S["安全、秘密与依赖扫描"]
    S --> B["可复现构建与镜像"]
    B --> E["Compose Smoke Test"]
    E --> A["制品、报告与证据归档"]
```

- 快速门禁在每个 PR 运行；高成本性能、恢复和真实模型评测按标签、计划任务或发布候选运行。
- 真实模型评测不在不可信 Fork PR 中暴露密钥。
- 任何跳过必须有机器可读状态和原因，不能把 `SKIP` 显示为 `PASS`。
- 构建使用 Wrapper、锁定依赖或可重现配置，镜像记录基础镜像 Digest 与 SBOM。

## 发布、回滚与恢复

### 发布前

- 迁移兼容当前与前一应用版本，或明确需要停机窗口。
- 镜像、配置、Secret、数据库备份和搜索 Schema 可定位。
- Smoke Test、数据范围测试和关键指标基线通过。
- 新旧事件消费者在支持窗口内兼容。

### 回滚

- 应用回滚使用不可变版本制品，不在服务器上重新构建。
- 数据库优先采用向前修复；若迁移不可逆，发布前明确阻断旧应用回滚的边界。
- Elasticsearch 用新索引 + 别名切换，保留已验证旧索引的短期回退窗口。
- Prompt 和模型切换保留版本化回退，不能覆盖历史配置。

### 恢复演练

至少覆盖：

1. 从 MySQL 备份恢复业务事实。
2. 从权威数据重建 Elasticsearch。
3. 重放 Outbox 或 Kafka 消费并验证幂等。
4. 恢复对象存储引用与内容散列校验。
5. 比较恢复前后的核心计数、指标和权限抽样。
6. 记录实际恢复时间与数据恢复点，再决定 RTO / RPO 目标。

## 可投递版本门禁

### 版本 A：后端业务闭环

- Java、MySQL、Flyway、MyBatis、权限、导入与指标测试通过。
- 合成数据可以重建固定 NPS / NSS 和 Top 问题答案。
- 越权、重复、部分失败和迁移升级用例通过。
- README 能从 fresh clone 启动并演示。

### 版本 B：工程增强

- Go Worker、Kafka、Elasticsearch 与 Compose 主线可重放。
- 重复消费、积压、索引重建、优雅停机、发布回滚和备份恢复有证据。
- OpenTelemetry 能关联关键跨进程链路。
- 性能报告包含环境、数据、分位数、错误和瓶颈。

### 版本 C：AI 增强

- 分类、检索、报告草稿和只读 Agent 有固定评测。
- 权限泄漏、伪造指标、无证据引用和虚构写操作为零。
- 模型、Prompt、Schema、工具和数据集版本可定位。
- 模型、搜索和工具故障均有确定终态与降级演示。

具体简历表达见 [[VoiceInsight 求职展示与简历口径]]。

## 每次发布保存的证据

- Release 或完整 commit 标识及 Git 状态。
- 版本与依赖清单、SBOM 和镜像 Digest。
- 迁移、OpenAPI、事件和配置 Schema 版本。
- 自动化测试摘要及失败、跳过项。
- fixture 与 AI eval 数据集版本。
- 性能、评测、安全扫描和许可证报告。
- 关键成功、权限拒绝、降级和恢复 Trace。
- 已知限制、回滚点和下一版本不兼容事项。

原始大日志、完整 Trace 和生成数据留在代码仓库制品或专门存储中；本笔记仓库只记录方法、摘要和可定位标识。
