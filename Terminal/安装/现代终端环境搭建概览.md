这是一篇**路线入口**，负责回答“我现在应该打开哪篇笔记”，不再维护另一套安装命令。

> [!important]
> 先按当前机器状态选择**一条主线**，从头执行到验收；主线中的专题链接只用于理解、个性化配置或排障，不是完成安装的必经步骤。

## 最终会得到什么

这套环境由几层职责不同的工具组成：

| 层次 | 工具 | 负责什么 |
| --- | --- | --- |
| 配置资产 | Git + GNU Stow | 保存配置源文件，并把它们链接到 `$HOME` 下的目标位置 |
| 终端模拟器 | Ghostty | 在本机提供窗口、字体、配色和键盘交互 |
| Shell | Zsh | 解析命令、读取启动文件并承载交互环境 |
| Zsh 插件管理 | Antidote | 下载、排序和加载 Zsh 插件；不管理其他命令行工具 |
| 提示符 | Starship | 生成当前目录、Git 状态和运行时信息 |
| 历史 | Atuin | 搜索和管理命令历史 |
| 目录导航 | zoxide | 按使用频率跳转目录 |
| 模糊查找 | fzf | 为历史、文件和目录选择提供交互式筛选 |

搭建过程同时建立一个可迁移的 dotfiles 仓库。它至少应包含：

- 一份说明源目录、部署方法和恢复边界的 `README.md`；
- 一组与 Zsh 启动依赖闭合的 Stow 软件包：命令行主线至少是 `zsh`、`atuin`、`starship`，macOS 桌面主线再包含 `ghostty`；
- 可复核的符号链接和一份已知可用的 Git 提交；
- 留在 Git 之外的本机配置、历史、密钥和运行数据。

这里的软件包列表不是“安装了哪些程序”，而是“哪些配置必须由 Git + Stow 成为第一写入者”。zoxide 数据库、fzf Shell 集成、Antidote 下载目录和生成缓存不需要独立软件包；它们分别属于运行数据、启动逻辑或可再生成内容。不要为未来配置预建空目录。

> [!important] 先闭合配置，再做真实初始化
> 只要 `.zshrc` 会调用某个组件，而该组件的配置又准备交给 Stow，就必须先在仓库中写好配置源、部署完整软件包列表并确认目标是链接，之后才能运行 `zsh -ic`、`zsh -lic`、`atuin info`、`atuin doctor`，或首次打开 Ghostty。`zsh -n` 只解析文件，不执行初始化，因此可以在 Stow 之前运行。

这是“首次写入所有权”规则：受管配置的第一写入者应是 Git + Stow，应用只负责 data、state 和 cache。否则应用可能先生成普通文件，后续 Stow 会把它识别为冲突；仅临时设置 `ZDOTDIR` 也不能隔离这种写入，因为 `$HOME` 与 XDG 目录仍是真实目录。

“新建 dotfiles”与“从远端恢复 dotfiles”是两种不同状态，不能混着执行。若 `$DOTFILES_DIR` 已存在但来源不明，先停下来检查仓库状态、远端地址和现有链接，不要覆盖后再判断。

## 本地桌面与远程主机的边界

Ghostty 是运行在**本地桌面系统**上的终端模拟器。通过 Ghostty SSH 到服务器时，服务器只需要 Shell 和命令行工具，不需要再安装 Ghostty。

| 使用场景 | Ghostty 放在哪里 | Zsh 与命令行工具放在哪里 |
| --- | --- | --- |
| macOS 本机开发 | macOS | macOS |
| macOS 通过 SSH 登录 Ubuntu | macOS | macOS 与 Ubuntu 分别安装、分别验证 |
| Ubuntu 桌面直接使用 | Ubuntu 桌面 | Ubuntu 桌面 |
| 无桌面的 Ubuntu 服务器或容器 | 不安装 | Ubuntu 服务器或容器 |

## 共同的完成边界

无论选择哪条主线，只有同时满足以下条件，才算完成一次可迁移的搭建：

1. 已区分账号登录 Shell、当前进程和继承的 `$SHELL`，没有只凭一个变量判断切换成功。
2. 已说清 dotfiles 的 Git 仓库、Stow 软件包、源文件和 `$HOME` 目标路径，并检查了实际链接。
3. 在任何真实 Zsh 或 Ghostty 初始化之前，已部署 `.zshrc` 会读取的全部受管配置，并确认这些目标不是应用生成的普通文件。
4. `.zshenv` 保持最小，只放所有 Zsh 进程都需要的环境；交互逻辑位于 `.zshrc`。
5. `.zprofile`、`.zshrc`、共享配置、平台配置和本机私有配置各有明确职责。
6. Starship、Atuin、zoxide、fzf 与插件清单已按实际安装情况初始化并验证；初始化后再次检查受管目标仍是链接。
7. 提交前检查了 `git status`、`git diff --cached` 和秘密边界，历史、密钥、缓存与本机私有值没有进入 Git。
8. 已形成一份已知可用提交；历史导入、云同步、主题美化等高变动操作放在该基线之后。

配置解析成功、命令存在、符号链接正确、交互式 Shell 可用、登录 Shell 已切换，是不同层级的证据。主线会分别验证，不会用某一层替代全部结论。
