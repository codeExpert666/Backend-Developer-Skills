本文建立一套处理文件与目录的最小工作流：先定位当前上下文并只读核对目标，再执行最小范围的创建、复制、移动或删除，随后验证结果；若中途失败，则保留现场并判断恢复方式。目标不是背完所有参数，而是能够安全完成日常操作，并在忘记选项时知道怎样查证。

本篇默认使用 Ubuntu Server 中的 Bash 普通用户会话。阅读第 1～5 章前，应先理解 [[Shell 命令结构、类型与帮助系统]]、[[Shell 路径、变量、引用与展开]]，以及 [[Shell 标准流、管道、重定向与退出状态]] 中的退出状态和命令列表。第 6 章是综合练习，执行前还应能读懂 [[Shell 脚本阅读基础]] 中的条件、分支与圆括号分组。本篇只解释这些 Shell 结构在文件操作中的作用，不重复维护完整语法。

如何查看或搜索文件内容，见 [[Linux 文本查看、搜索与处理常用命令]]；权限和磁盘布局分别由对应专题负责。

## 1. 先理解路径与文件对象

Linux 把文件组织成一棵从 `/` 开始的目录树。命令操作的不是“屏幕上看到的名字”，而是某个路径经过 Shell 展开后指向的对象。

- **当前工作目录**：Shell 解释相对路径时采用的起点，可用 `pwd` 查看。
- **绝对路径**：从 `/` 开始，例如 `/etc/ssh/sshd_config`。
- **相对路径**：从当前工作目录开始，例如 `docs/readme.md`。
- `.`：当前目录。
- `..`：上一级目录。
- `~`：由 Shell 展开的当前用户主目录。

本篇主要涉及三类文件系统对象：普通文件保存数据；目录保存名称与下一级对象之间的对应关系；符号链接（symbolic link）保存一段指向其他路径的引用。符号链接指向的目标不存在时，称为失效符号链接。删除链接本身不会删除其目标，但会跟随链接的检查可能把失效链接判断为“不存在”。

相同命令对不同对象类型可能产生不同结果；例如复制目录通常需要递归选项。路径文字相同也不代表结果相同：只要当前工作目录发生变化，相对路径的含义就会随之改变。硬链接、访问控制列表（Access Control List，ACL）和扩展属性不在本篇展开。

## 2. 掌握目标与命令选择

本节只建立后续阅读地图，不要求在这里理解每条命令的选项；具体对象、语法和风险会在后文按使用顺序展开。

| 层级 | 应达到的程度 | 命令与能力 |
| --- | --- | --- |
| 必须熟练 | 能先核对目标，再完成基本文件操作并验证结果 | `pwd`、`cd`、`ls`、`mkdir`、`touch`、`cp`、`mv`、`rm` |
| 理解会查 | 知道它们回答什么问题，复杂参数按需查 | `rmdir`、`file`、`stat`、`realpath`、`basename`、`dirname`、`find`、`du`、`df` |
| 认识即可 | 看到时知道用途，不在本篇展开 | 符号链接、硬链接、访问控制列表（ACL）、扩展属性、`find` 的复杂表达式与动作 |

“必须熟练”不等于背下全部选项，而是能在执行前回答：源路径是什么、目标路径是什么、是否会覆盖、是否会递归、如何验证、失败后还能保留什么。

按问题选择命令，比按字母记忆更容易迁移：

| 要回答的问题 | 优先想到的命令 |
| --- | --- |
| 我在哪里，目录中有哪些对象 | `pwd`、`cd`、`ls` |
| 这个路径指向什么对象 | `file`、`stat`、`realpath` |
| 某类文件位于哪里 | `find` |
| 目录用了多少空间，所在文件系统还剩多少空间 | `du`、`df` |
| 创建、复制、移动或删除对象 | `mkdir`、`touch`、`cp`、`mv`、`rm`、`rmdir` |

忘记参数时，外部命令通常先查看 `COMMAND --help` 或 `man COMMAND`；`cd` 等 Shell 内建命令可以使用 `help cd`。命令结构和帮助系统的完整方法见 [[Shell 命令结构、类型与帮助系统]]。

## 3. 统一安全操作循环

文件操作不应从“我要输入哪条命令”开始，而应先建立同一套判断顺序：

```text
确认执行位置
    -> 识别源对象、目标位置和预期结果
    -> 判断会改变哪些对象以及能否恢复
    -> 执行最小范围的操作
    -> 检查退出状态和操作后状态
    -> 失败时保留现场并选择恢复方式
```

### 3.1 执行前核对

先区分四类经常被混在一起的风险：

| 风险 | 含义 | 为什么需要提前判断 |
| --- | --- | --- |
| 覆盖 | 已有目标的内容或目录项可能被新结果替换 | 命令成功也可能造成旧内容丢失 |
| 递归 | 操作会进入目录并影响其下多层对象 | 实际范围可能远大于命令行中写出的一个路径 |
| 跨文件系统 | 源和目标由不同文件系统承载 | 移动可能不再只是改名，而会涉及复制和删除 |
| 删除 | 目录项或数据会被移除 | 命令通常没有通用撤销能力，恢复依赖事先建立的副本或机制 |

实际操作前至少确认以下问题：

1. 当前 Shell 位于哪个目录，相对路径将从哪里解析？
2. 源对象是否存在，它是文件、目录还是符号链接？
3. 目标路径是否已经存在；若存在，它是什么类型？目标若是失效的符号链接，也不能当作名称完全空闲。
4. 操作会改变哪些对象，是否包含覆盖、递归、跨文件系统或删除风险？
5. 计划用什么结果证明操作符合预期？
6. 如果中途失败，哪些现场需要保留，恢复依赖什么？

第 4 章会先逐个介绍只读观察工具，再在第 4.5 节把它们组合成可按任务裁剪的预检模板。

### 3.2 执行后验证

退出状态为 `0` 只表示命令认为自己成功完成，不自动证明结果符合人的意图。例如，预期把文件改成一个新名称，实际却把它放进了一个已有目录时，操作仍可能成功。

因此，变更后还要逐项核对后置条件：

1. 预期的新路径是否存在，对象类型是否正确？
2. 旧路径应该保留还是消失，它是否处于预期状态？
3. 重要内容或元数据是否需要额外比对？
4. 操作范围之外的对象是否保持不变？
5. 若命令失败，最后成功到哪一步，现场是否仍可用于判断和恢复？

第 4.5 节会在相关命令介绍完毕后给出后置条件模板；第 5 章再把这套循环应用到创建、复制、移动和删除。

### 3.3 按风险选择操作方式

| 操作性质 | 主要影响 | 执行前后的重点 |
| --- | --- | --- |
| 只读观察 | 不主动改变文件内容或目录项，但可能扫描大量对象或显示敏感路径 | 限定观察范围，判断输出是否完整并避免泄露 |
| 当前会话变化 | 改变后续命令解释路径或变量的上下文 | 变更后重新确认当前位置和变量值 |
| 创建或更新时间 | 新增对象，或改变已有对象的时间信息 | 核对父目录、名称是否空闲及最终对象类型 |
| 复制、移动或覆盖 | 写入目标，可能替换已有内容或消耗额外空间 | 分别核对源和目标，并验证内容、旧路径和新路径 |
| 删除 | 移除目录项或目录树 | 先确认恢复能力和精确范围，失败时保留现场 |

在系统目录中加入 `sudo` 不只是“让命令成功”，而是让变更以管理员权限发生。遇到权限错误时，应先检查对象归属、路径各级权限和正确管理方式，不要为了省事给日常项目操作加 `sudo`。详见 [[Linux 用户、用户组、sudo 与文件权限]]。

## 4. 只读观察与诊断

### 4.1 定位并查看目录

先确认当前位置，再进入 `$HOME` 指向的当前用户主目录并重新核对：

```bash
pwd
ls
ls -la
ls -ld -- "$HOME"
cd "$HOME"
pwd
```

- `pwd` 输出当前工作目录的绝对路径。
- `cd` 改变当前 Shell 的工作目录，因此它是 Shell 内建命令；子进程不能替父 Shell 改目录。
- `ls` 列出目录项；`-l` 使用长格式，`-a` 同时显示以 `.` 开头的名称。
- `ls -d` 在操作数是目录时显示目录项本身，而不是列出目录中的内容；`ls -ld -- PATH` 因此适合核对目标目录或符号链接本身的元数据。`--` 表示选项到此结束，后面的内容按操作数解释，可避免以 `-` 开头的名称被误当成选项。
- `cd -` 返回前一个工作目录；单独执行 `cd` 通常回到当前用户主目录。

`ls -l` 显示的是目录项元数据摘要，不等于文件内容，也不能证明当前用户真的可以完成某项操作。查看和搜索文件内容应使用 [[Linux 文本查看、搜索与处理常用命令]]；权限问题应结合 [[Linux 用户、用户组、sudo 与文件权限]] 判断。

### 4.2 识别对象并解析路径

```bash
file /etc/os-release
stat /etc/os-release
stat -c 'type=%F owner=%U:%G mode=%a size=%s path=%n' /etc/os-release
realpath /etc/os-release
basename /var/log/syslog
dirname /var/log/syslog
```

- `file` 读取内容特征，判断文本、可执行文件、压缩包等类型；它不只依赖扩展名。
- `stat` 显示类型、大小、权限、所有者和时间戳等元数据。
- `realpath` 规范化路径，并在允许的情况下解析其中的符号链接；缺失或不可访问的路径组件可能使它失败，应同时检查退出状态。
- `basename` 只取路径最后一段。
- `dirname` 只取最后一段之前的部分。

`basename` 和 `dirname` 处理的是路径字符串，不负责验证对象是否存在；`file`、`stat` 和 `realpath` 则会访问文件系统。需要核对符号链接时，不要只看 `realpath` 的最终结果，还要用 `ls -ld` 或 `stat` 区分链接本身和目标对象。

### 4.3 按条件定位对象

下面假设 `$HOME/src` 已存在；若实际工作区不同，应先替换并核对起始路径：

```bash
find "$HOME/src" -maxdepth 2 -type d -print
find "$HOME/src" -type f -name '*.log' -print
find "$HOME/src" -type f -size +100M -print
```

`find` 的基本顺序是“起始路径 → 测试条件 → 动作”。`'*.log'` 必须引用，否则 Shell 可能在 `find` 运行前就在当前目录展开通配符。初学阶段优先使用只读的 `-print`；`-delete` 和 `-exec` 等动作要在明确执行范围后再学习。

`find` 主要根据名称、类型、大小等条件查找文件系统对象；在文本内容中找匹配行通常使用 `grep` 或其他文本搜索工具，见 [[Linux 文本查看、搜索与处理常用命令#4.3 用 grep 找到需要的行|使用 grep 搜索文本]]。

### 4.4 检查目录占用与文件系统容量

下面同样假设 `$HOME/src` 已存在：

```bash
du -sh "$HOME/src"
du -h --max-depth=1 "$HOME/src"
df -hT "$HOME/src"
```

- `du` 汇总目录树中文件占用，回答“这个目录用了多少空间”。
- `df` 查看路径所在文件系统的整体容量与剩余空间，回答“这个文件系统还有多少空间”。
- `du` 与 `df` 的统计边界不同，结果不必完全一致。已删除但仍被进程打开的文件、文件系统保留空间和稀疏文件都可能造成差异。

扫描大目录可能耗时，也可能因权限不足而得到不完整结果。磁盘、挂载和文件系统概念见 [[Linux 磁盘、分区、文件系统与 LVM 基础]]。

### 4.5 把只读工具组合成预检与后置验证

前面已经分别说明了当前位置、对象类型、真实路径、查找范围和容量边界。现在再把这些工具组合起来，读者不需要跳到后文猜测每条命令的作用。下面都是可按任务裁剪的结构，不是每次操作都要机械执行的固定清单。

#### 操作前预检

Bash 内建的 `printf` 支持 `%q` 格式，它会把参数输出成可供 Shell 重新读取的转义形式，便于发现路径中的空格、换行或其他特殊字符。它只负责显示变量当前保存的值，不能证明该路径安全或对象存在。

```text
pwd
printf '%q\n' "$PATH_TO_CHECK"
ls -ld -- "$SOURCE_PATH"
ls -ld -- "$DESTINATION_PATH"
file -- "$SOURCE_PATH"
stat -- "$SOURCE_PATH"
realpath -- "$SOURCE_PATH"
```

变量名是说明性占位符，必须先赋为已经核对的真实路径，不能把整段原样执行。目标预期尚不存在时，针对目标的 `ls` 返回非零状态可能正是预期结果；`file`、`stat` 或 `realpath` 遇到缺失、失效链接或不可访问的路径也可能失败。这些状态应进入判断，不能为了得到整齐输出而隐藏。

实际任务应根据问题选择命令：核对目录项本身优先使用 `ls -ld` 或 `stat`；判断内容类型使用 `file`；需要规范化并跟随符号链接时再使用 `realpath`。只看 `realpath` 的最终目标，不能代替对符号链接本身的检查。

#### 操作后验证

`test` 通过退出状态表达条件真假。`-e` 判断路径解析后是否存在对象，`-f` 和 `-d` 分别判断普通文件与目录，`-L` 判断路径名是否对应符号链接。由于 `-e` 会跟随符号链接，失效链接可能得到假值；要证明某个目录项已经消失，需要同时确认它既不解析为对象，也不是符号链接。

```text
test -e "$EXPECTED_PATH" || test -L "$EXPECTED_PATH"
test ! -e "$REMOVED_PATH" && test ! -L "$REMOVED_PATH"
ls -ld -- "$RESULT_PATH"
stat -- "$RESULT_PATH"
find "$CHECK_ROOT" -maxdepth "$MAX_DEPTH" -print
```

若结果必须是普通文件、目录或符号链接，应分别改用 `test -f`、`test -d` 或 `test -L`，不能只证明“某种对象存在”。`&&` 只在左侧成功时继续，`||` 只在左侧失败时继续；完整条件组合见 [[Shell 脚本阅读基础#6. 使用 test 表达条件|test 条件判断]]，退出状态和命令列表见 [[Shell 标准流、管道、重定向与退出状态]]。

后置验证必须围绕预期结果选择：复制要检查目标类型和必要的内容一致性；移动要同时检查新、旧两端；删除则要证明目标目录项消失。看到同名路径或一次退出状态为 `0`，都不能单独证明人的意图已经实现。

## 5. 创建、复制、移动与删除

下面开始执行会改变文件系统状态的操作。语法骨架使用中文占位符，因此声明为 `text`，不能原样执行；实际操作时应代入已经核对的路径，并按照“预检 → 操作 → 后置验证”完成闭环。

| 命令 | 产生的变化 | 首要风险 |
| --- | --- | --- |
| `mkdir`、`touch` | 创建对象或更新时间戳 | 落点错误；已有对象被改变 |
| `cp` | 保留源对象并写入目标 | 覆盖目标、空间不足、元数据不能完整保留 |
| `mv` | 改变名称或位置 | 目标解释错误、覆盖、跨文件系统时涉及复制与删除 |
| `rm`、`rmdir` | 删除文件、链接或目录 | 影响范围过大，且通常不能直接撤销 |

### 5.1 创建文件和目录

`mkdir` 创建目录；`mkdir -p` 还会创建路径中缺失的父目录。目标已经作为目录存在时，`-p` 不会因此报错，但路径中的已有对象若不是目录，命令仍会失败。`touch` 的本义是更新时间戳，目标不存在时通常会创建空文件；目标已经存在时，它会改变时间信息。

执行前先用 `pwd` 和 `ls -ld -- 父目录路径` 核对落点，并确认最终名称是否已经被占用：

```text
mkdir 目录路径
mkdir -p 多级目录路径
touch 文件路径
```

创建后使用 `test -d 目录路径`、`test -f 文件路径` 或 `stat` 检查对象类型。`touch` 不会为文件写入正文，也不是编辑器，不能把它当成完全无影响的“存在性检查”。

### 5.2 复制文件或目录树

`cp` 保留源对象并创建目标副本。复制目录树时，`cp -a` 会递归复制，并尽量保留符号链接、权限和时间等属性；能否完整保留仍受目标文件系统和执行身份限制。

目标路径的形态会改变结果：如果目标是已有目录，源对象通常被放进该目录；如果目标不存在，命令通常以该名称创建副本；如果目标是已有文件，则可能发生覆盖。执行前必须分别核对源和目标，不能因为目标不存在使 `ls` 返回非零状态，就跳过“它是否应该不存在”的判断。

```text
cp 源文件 目标文件
cp -a 源目录 目标目录
```

复制完成后，至少检查命令退出状态、目标是否存在及类型是否正确。迁移重要数据时，还应采用适合数据类型的内容比对或校验方式；看到一个同名目标，并不能证明内容完整。

### 5.3 移动或重命名

`mv` 可以重命名，也可以把对象移动到另一个目录。与 `cp` 一样，已有目录会改变目标解释，已有文件还可能面临覆盖风险，因此必须先分别核对源和目标。

同一文件系统内的普通重命名通常只改变目录项；源和目标位于不同文件系统时，`mv` 可能变成“复制到目标后再删除源对象”，不再是同一文件系统中的原子重命名。无法确认边界或迁移重要目录时，优先采用“复制 → 验证目标 → 单独处理源目录”的可恢复流程。

```text
mv 源路径 目标路径
```

操作后应同时验证两项：新路径符合预期，旧路径也处于预期状态。只检查其中一端，无法证明移动或重命名完整完成。

### 5.4 删除明确目标

`rm` 删除文件或符号链接，默认不能删除目录；`rmdir` 只删除空目录，可以把“目录必须为空”作为保护条件；`rm -r` 会递归进入并删除整个目录树，影响范围明显更大。

删除不存在通用的命令级回滚。恢复通常依赖备份、版本控制、快照或应用自身的恢复机制，因此恢复能力必须在删除前建立，而不是删除后补救。

> [!warning] `rm` 默认不会进入回收站
> 在服务器终端中，删除通常不可直接撤销。不要对尚未展开确认的变量、通配符、`/`、`$HOME` 或陌生目录运行递归删除。先用 `printf '%q\n' "$TARGET"`、`ls -ld -- "$TARGET"` 和 `find "$TARGET" -maxdepth 2 -print` 核对目标；确认存在有效备份或目标确实可重建后，再执行最小范围删除。

完成上述检查后，才从与目标匹配的最小命令开始：

```text
rm -- 待删除文件
rmdir -- 待删除空目录
rm -r -- 待递归删除目录
```

`rm -f` 的主要作用是忽略不存在的文件并取消部分交互提示，不代表“更彻底”，也不会让危险操作更安全。删除后同时使用 `test ! -e 目标路径` 和 `test ! -L 目标路径` 验证目录项确实消失；如果删除失败，不要未经核对就升级为 `sudo rm -rf`，而应先检查对象类型、目录内容、权限和挂载边界。

## 6. 分阶段安全练习

下面的练习只操作 `mktemp` 创建的独立临时目录，不需要 `sudo`。请在同一个 Bash 会话中按顺序执行；每一阶段开始前先预测将看到什么，不要跳过路径核对。

> [!info] 执行前提
> 本章检验文件操作，不负责第一次教授 Shell 脚本语法。执行前应能读懂变量与命令替换、退出状态、`if`、`test`、`&&`、重定向和圆括号分组；若其中任一结构陌生，先回到开头列出的 Shell 专题完成对应最小主线。

这些结构在本练习中的职责如下：

| 结构 | 本练习中的作用 |
| --- | --- |
| `LAB_DIR="$(mktemp -d /tmp/file-command-lab.XXXXXX)"` | `mktemp -d` 创建目录并用六个随机字符替换 `XXXXXX`；命令替换取得实际路径并保存到当前 Shell 变量 |
| `if ...; then ... fi` | 根据命令或命令列表的退出状态选择成功、失败分支 |
| `( ... )` | 在子 Shell 中执行一组命令，使其中的 `cd` 不改变外层 Shell 的工作目录 |
| `&&` | 只有前一步成功才继续，避免中间失败后仍执行后续变更 |
| `>`、`>&2` | 分别把输出写入文件，或把错误提示发送到标准错误 |
| `${LAB_DIR:-}`、`[[ ... ]]` | 在变量未设置或为空时得到空值，并用 Bash 模式继续限制允许的清理路径 |

这里只说明场景职责。变量与命令替换的完整规则见 [[Shell 路径、变量、引用与展开]]；状态、命令列表和重定向见 [[Shell 标准流、管道、重定向与退出状态]]；分支、条件和子 Shell 见 [[Shell 脚本阅读基础]]。

### 6.1 创建练习目录并完成操作

代码块中的操作使用 `&&` 串联：任一步返回非零状态，后续步骤就不会继续。失败时临时目录会保留，便于检查，而不会自动清理证据。

```bash
if LAB_DIR="$(mktemp -d /tmp/file-command-lab.XXXXXX)"; then
  printf 'lab=%s\n' "$LAB_DIR"

  if (
    cd -- "$LAB_DIR" &&
    mkdir -p project/docs &&
    touch project/docs/readme.txt &&
    printf '%s\n' 'Linux command lab' > project/docs/readme.txt &&
    pwd &&
    ls -la project/docs &&
    file project/docs/readme.txt &&
    stat -c 'type=%F size=%s path=%n' project/docs/readme.txt &&
    cp project/docs/readme.txt project/docs/readme.backup.txt &&
    test -f project/docs/readme.backup.txt &&
    mv project/docs/readme.backup.txt project/docs/readme.old.txt &&
    test ! -e project/docs/readme.backup.txt &&
    test ! -L project/docs/readme.backup.txt &&
    test -f project/docs/readme.old.txt &&
    find project -maxdepth 3 -print &&
    du -sh project &&
    df -hT "$LAB_DIR"
  ); then
    printf '%s\n' 'PASS: 操作阶段完成，练习目录已保留供复查。'
  else
    printf 'FAIL: 操作阶段中止，请检查并保留目录：%s\n' "$LAB_DIR" >&2
  fi
else
  printf '%s\n' 'FAIL: 无法创建练习目录，未执行后续文件操作。' >&2
fi
```

成功时，`find` 应显示 `project/`、`project/docs/`、`readme.txt` 和 `readme.old.txt`，但不再显示 `readme.backup.txt`。`du` 与 `df` 的具体数字取决于运行环境，不要求相同。若出现 `FAIL`，先使用输出的 `lab=` 路径检查最后成功到哪一步，不要立即运行清理阶段。

### 6.2 删除前只读预览

`${LAB_DIR:-}` 在变量未设置或值为空时展开为空字符串，因此第一项 `test -n` 会失败并阻止后续操作。`[[ "$LAB_DIR" == /tmp/file-command-lab.?????? ]]` 使用 Bash 模式匹配；每个 `?` 代表恰好一个字符，用来要求路径符合本练习的固定前缀和六字符随机后缀。

路径形状本身不能证明目录来源正确，因此还要同时要求变量非空、目标是目录而不是符号链接，并在输出后由人核对实际路径和对象集合：

```bash
if test -n "${LAB_DIR:-}" &&
   test -d "$LAB_DIR" &&
   test ! -L "$LAB_DIR" &&
   [[ "$LAB_DIR" == /tmp/file-command-lab.?????? ]]; then
  printf 'cleanup-target=%q\n' "$LAB_DIR"
  find "$LAB_DIR" -maxdepth 3 -print
else
  printf '%s\n' 'FAIL: 练习目录校验失败，拒绝预览和删除。' >&2
fi
```

只有当输出路径和对象集合都符合预期，并且不再需要保留失败现场时，才继续清理。

### 6.3 按明确顺序清理并验证

下面沿用上一节的变量、对象类型和路径模式保护。本练习故意不使用 `rm -r`：先删除两个已知文件，再用 `rmdir` 逐层删除空目录；若出现额外对象，`rmdir` 会失败并保留现场。

```bash
if test -n "${LAB_DIR:-}" &&
   test -d "$LAB_DIR" &&
   test ! -L "$LAB_DIR" &&
   [[ "$LAB_DIR" == /tmp/file-command-lab.?????? ]]; then
  if rm -- "$LAB_DIR/project/docs/readme.old.txt" &&
     rm -- "$LAB_DIR/project/docs/readme.txt" &&
     rmdir -- "$LAB_DIR/project/docs" &&
     rmdir -- "$LAB_DIR/project" &&
     rmdir -- "$LAB_DIR"; then
    printf '%s\n' 'PASS: 练习目录已按明确目标清理。'
  else
    printf 'FAIL: 清理未完成，请重新检查：%s\n' "$LAB_DIR" >&2
  fi
else
  printf '%s\n' 'FAIL: 练习目录校验失败，拒绝删除。' >&2
fi
```

最后执行：

```bash
if test -n "${LAB_DIR:-}" &&
   test ! -e "$LAB_DIR" &&
   test ! -L "$LAB_DIR"; then
  printf '%s\n' 'PASS: 练习目录已不存在。'
else
  printf '%s\n' 'FAIL: 无法证明练习目录已删除。' >&2
fi
```

## 8. 常见误解

| 误解 | 正确认识 |
| --- | --- |
| `ls` 没显示就是目录为空 | 隐藏名称需要 `ls -a`；权限也可能限制读取 |
| `ls` 可以查看文件内容 | `ls` 查看目录项及其元数据摘要，文件内容应使用文本查看工具 |
| 文件扩展名决定类型 | Linux 不强制依赖扩展名，`file` 会检查内容特征 |
| `touch` 只是创建空文件 | 它也会更新已有对象的时间戳 |
| `cp -r` 与 `cp -a` 永远等价 | `-a` 还试图保留链接和多种元数据 |
| `mv` 永远只是改目录项 | 跨文件系统时可能包含复制与删除 |
| `rm -f` 更适合日常使用 | 它会减少保护性反馈，不会降低删除风险 |
| `find` 与 `grep` 都是在找文件 | `find` 主要定位文件系统对象，`grep` 主要匹配文本内容 |
| `du` 和 `df` 应给出同一个数字 | 两者观察范围和统计来源不同 |
| `test ! -e PATH` 能证明任何类型的目录项都不存在 | 它可能把失效符号链接判断为不存在；还要结合 `test ! -L PATH` |
| 退出状态为 `0` 就证明结果符合意图 | 它只证明命令认为执行成功，仍需核对目标路径和后置条件 |
| 路径以 `/` 开头只是写法不同 | 它是从根目录解析的绝对路径，与当前目录无关 |
